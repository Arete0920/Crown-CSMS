# ACCOUNTING ARCHITECTURE RULES

## NON-NEGOTIABLE RULES

1. ALL FINANCIAL TRANSACTIONS MUST USE DOUBLE ENTRY ACCOUNTING.

2. LEDGER ENTRIES ARE IMMUTABLE.
   NO UPDATE OR DELETE ALLOWED.

3. REVERSALS MUST USE COMPENSATING ENTRIES.

4. EVERY FINANCIAL EVENT MUST BE TRACEABLE.

5. EVERY TRANSACTION MUST HAVE:
   - tenant_id
   - created_by
   - correlation_id
   - timestamp
   - source_system

6. FLOATING POINT TYPES ARE FORBIDDEN.
   ONLY DECIMAL TYPES ALLOWED.

7. ALL MONEY VALUES MUST INCLUDE:
   - amount
   - currency

8. CROSS-TENANT ACCESS IS FORBIDDEN.

9. ACCOUNT BALANCES ARE DERIVED.
   NEVER STORED AS SOURCE OF TRUTH.

10. ACCOUNTING LOGIC MAY NOT EXIST INSIDE UI LAYERS.

11. DIRECT DATABASE WRITES TO LEDGER TABLES ARE FORBIDDEN OUTSIDE AUTHORIZED SERVICES.

12. ALL ACCOUNTING SERVICES REQUIRE:
   - verification tests
   - reconciliation tests
   - integrity tests
   - audit tests

13. ALL ACCOUNTING EVENTS MUST BE IDEMPOTENT.

14. SOFT DELETE IS FORBIDDEN FOR LEDGER RECORDS.

15. EVERY FINANCIAL ACTION MUST GENERATE AUDIT RECORDS.

16. ALL FINANCIAL EXPORTS REQUIRE AUDIT LOGGING.

17. MANUAL SQL CHANGES TO ACCOUNTING TABLES ARE FORBIDDEN.

18. ALL MIGRATIONS REQUIRE VERIFICATION APPROVAL.

19. ACCOUNTING CODE CANNOT BE AUTO-GENERATED WITHOUT HUMAN REVIEW.

20. COPILOT AUTONOMOUS AGENT EXECUTION IS FORBIDDEN IN ACCOUNTING MODULES.

immutable ledger enforcement is mandatory.
