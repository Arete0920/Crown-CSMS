## Evidence interpretation

A green workflow proves only the controls executed for its exact SHA and configuration. A merged PR proves that its reviewed delta reached history; it does not automatically prove a later `main`. Open issues and surviving branches must be reconciled before handoff so historical residue is not mistaken for an active defect and an active defect is not mislabeled as historical residue.

Deployment, runtime health, backup/restore, credential rotation, external integrations, payment processing, and successor account control require their own evidence where applicable.

## Buyer-safe statement

Crown-CSMS is the active successor engineering and owner-turnover repository. The current GitHub `main` SHA plus evidence generated for that same SHA control repository handoff claims. Production deployment, legal/compliance conclusions, payment activation, and final successor acceptance are separate claims and must not be inferred from repository evidence.
