# Sandbox Issue Triage and Daily Cadence

## Purpose

This document defines how the CROWN team receives, classifies, assigns, and reviews sandbox feedback during Tier 0 and Tier 1.

## Priority levels

| Priority | Definition | Response goal |
|----------|------------|---------------|
| P0 | Blocks login, wrong school context, or blocks the trial for multiple reviewers | Same day |
| P1 | Blocks a major workflow for one or more reviewers | Same or next business day |
| P2 | Confusing workflow, unclear wording, missing field, or repeated usability issue | Triage during daily review |
| P3 | Feature request, preference, or improvement idea | Capture and review weekly |
| P4 | Future roadmap suggestion | Capture for product review |

## Daily cadence

### Morning review

- Review new P0/P1 issues.
- Confirm whether Tier 0 or Tier 1 can continue.
- Assign owners for urgent fixes or clarifications.
- Update the known-issues note if needed.

### Midday check

- Confirm login/access reports.
- Confirm support response time.
- Check for repeated confusion across reviewers.
- Identify whether school-facing instructions need clarification.

### End-of-day review

- Count new issues by priority.
- Identify common themes.
- Close resolved items with proof or explanation.
- Decide whether the next tier remains blocked, watch, or clear.

## Required issue fields

Each issue should capture:

- school or reviewer name,
- role or reviewer type,
- page or workflow,
- expected result,
- actual result,
- priority,
- owner,
- current status,
- resolution notes.

## Tier advancement rule

Do not advance to the next tier while any P0 remains open. Do not advance while a repeated P1 issue affects the main sandbox evaluation path.

## Daily summary format

Use this daily summary:

```text
Date:
Tier:
Schools/reviewers active:
New P0:
New P1:
New P2:
Top three themes:
Resolved today:
Open blockers:
Decision: continue / hold / expand
```
