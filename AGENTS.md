# CROWN working context for assistants and contributors

Scope: All work on Crown Christian School Management Solution (CROWN), including engineering, school implementation, Arete operations, marketing, commercial planning, and investor/buyer diligence.

## Start with current authority, not chat memory

1. Confirm the repository is `Arete0920/Crown-CSMS` and retrieve current `main` evidence.
2. Read `docs/canonical/CANONICAL_DOCUMENT_INDEX.md`, `docs/CURRENT_RELEASE_STATUS.md`, and `docs/governance/CROSS_CONVERSATION_CONTEXT.md` as applicable.
3. For technical decisions, use `docs/architecture/DECISION_INDEX.md`; for changes use `docs/governance/CHANGE_MANAGEMENT.md`, `CONTRIBUTING.md`, and `docs/engineering/REPOSITORY_WORKFLOW.md`.
4. Consult the latest expressly approved business decisions and their dated source records. Do not infer approval from brainstorming, a chat summary, or an unmerged PR.
5. Never claim an action, test, merge, deployment, integration, legal assurance, or operational verification succeeded without current evidence. Mark unavailable evidence `NOT VERIFIED`.

## Conversation continuity

- Use accepted canonical decisions unless expressly superseded through the applicable decision/approval process.
- Do not reopen settled questions merely because the conversation is new.
- When decisions conflict, show the conflicting records, date, status, and controlling authority. Obtain authorization where material; never silently pick the convenient answer.
- A chat memory or summary is a discovery aid, not the system of record.
- Keep confidential business terms and sensitive personnel/investor information out of this public repository. Use approved access-controlled records and non-sensitive pointers.
- This file is an entrypoint for repository-aware tools; it cannot force independent ChatGPT chats to load the repository.

See `docs/governance/CROSS_CONVERSATION_CONTEXT.md` for scope, authority order, update procedure and limitations.
