# Crown System Architecture Overview

## Core Stack

| Layer | Technology |
|---|---|
| Backend | Django 5.x + Django REST Framework |
| Frontend | React 18 + Vite + MUI |
| Database | PostgreSQL (Azure DB for PostgreSQL Flexible Server) |
| Background Queue | Celery + Redis |
| Error Monitoring | Sentry |
| Hosting | Azure App Service (crown-api-prod) |
| Secrets | Azure Key Vault (crown-kv-prod, RBAC mode) |
| Container Registry | Azure Container Registry (admin disabled) |

## Canon Boundary Note

- **Crown Core owns system-of-record truth.**
- **Operational modules run school workflows.**
- **Crown Compass** is a leadership & strategy add-on, not a Crown Core module.
- **Crown Discernment** is positioned only as the explainable engine inside Crown Compass when later approved for implementation.
- **Crown Solomon** is the mission-aware guidance, onboarding, governance-template, interpretation, and playbook layer.

---

## Multi-Tenant Enforcement

- Every request must carry `X-School-Id` header (enforced by `TenantHeaderRequiredMiddleware`)
- All querysets are scoped by `school_id` at the service layer
- `get_request_school_id(request)` is the canonical scoping helper
- No cross-tenant access is permitted under any circumstance
- Role-based permission spine (`core.permissions`) controls module access per school

**Never bypass tenant enforcement. Every new endpoint must call `get_request_school_id()`.**

---

## API Version Policy

- `/api/v1/` — stable, minimum 18-month support window
- `APIVersionMiddleware` injects `X-API-Deprecated-After: 2027-01-01` on all `/api/v1/` responses
- New breaking API changes increment to `/api/v2/` — never silently break v1

---

## Key Architectural Invariants

1. `ledger.Payment` is **immutable** (`ImmutableMoneyMixin`) — never add fields to it
2. Billing unit is **Household**, not Student
3. `ledger.signals` validates `Payment.school_id` maps to a real `core.School`
4. `AUTH_USER_MODEL = core.UserAccount` — never reference `auth.User` directly
5. Celery tasks are thin wrappers — all logic lives in service modules
6. `ALLOW_DEMO_ROLE_HEADER = False` is **unconditional** in all environments

## Data Flow (Simplified)

```
Client (React)
    ↓  HTTPS + Bearer token
API Gateway (Azure App Service)
    ↓
Django REST (DRF)
    ↓  TenantHeaderRequiredMiddleware → get_request_school_id()
Service Layer (services_*.py)
    ↓
PostgreSQL (scoped by school_id)

Async paths:
Django → Celery (Redis broker) → Service Layer → PostgreSQL

External integrations:
- Payment Processor (Stripe stubs, wired via ledger/services_dunning.py)
- Email: Microsoft Graph (GRAPH_FROM_USER)
- Monitoring: Sentry (sentry_sdk)
```

## Deployment

- **CI/CD:** GitHub Actions (`.github/workflows/`)
- **Branch protection:** `main` requires 1 approving review + all checks passing
- **Prod deploy:** Tagged as `prod-deploy-YYYY-MM-DD`
- **Secrets:** All loaded from Azure Key Vault via App Service managed identity
- **Database migrations:** Run manually post-deploy: `python manage.py migrate`
